ADR-003 — Ampliación de alcance a editor Markdown completo (reapertura de Discovery y Roadmap)

Contexto: El requerimiento FUENTE-001 (requerimiento.txt) describe un editor Markdown completo: paneles WYSIWYG/Markdown sincronizados, edición, formato, enlaces, tablas, fórmulas, diagramas, índice, exportación a PDF, metadatos/propiedades y corrección ortográfica, entre otros. Lo implementado cubre solo F-001 (entorno de aplicación) y F-002 (gestión de archivo). El roadmap aprobado (v1, ROADMAP_APPROVED 2026-10-23) incluyó solo esas 2 features, dejando el resto del requerimiento fuera de alcance. Se solicita cubrir el requerimiento completo.

Decisión: Ampliar el alcance del proyecto para cubrir el requerimiento completo (editor Markdown completo) y reabrir Discovery y Roadmap; por ser funcionalidad fuera del alcance actual, este ADR documenta la decisión de iniciar Discovery (§4.2). En este paso no se implementa funcionalidad nueva: se inicia un nuevo ciclo de Discovery que redefina requisitos, dimensionado y roadmap.

Justificación: El requerimiento completo ya está sellado como FUENTE-001 y su cobertura bidireccional exige recuperar las capacidades omitidas por el filtro de relevancia del alcance anterior (D44). La reapertura evita ratificar pieza a pieza, mediante borradores PD, una falta de especificidad que pertenece a Discovery (§22). Impacto integrado: cambia el alcance aprobado y el dimensionado (M, ponderado 5,50; C1 alcance 8), con posible subida a L si el número real de Features supera la estimación inicial; reabre discovery-context, constraints, assumptions y Project Spec; afecta architecture.md (superficie y límites), constraints.md y el roadmap vigente; las Features F-001/F-002 implementadas se mantienen como base, pero sus Spec/Plan/Result pueden quedar stale hasta la propagación. Depende de revisar FUENTE-001 frente a lo ya sellado, re-evaluar la disparidad de Features (a) re-agrupación o (b) cambio de categoría, y re-gating de DISCOVERY_COMPLETE, PROJECT_SPEC_REVIEW y ROADMAP_APPROVED.

Consecuencias: Iniciar Discovery sobre el requerimiento completo; actualizar discovery-context, constraints, assumptions y Project Spec con trazabilidad a FUENTE-001; redefinir el roadmap con todas las Features del requerimiento y su línea «Valor utilizable» (D46); archivar con sdd-version las versiones afectadas y actualizar el checkpoint con sdd-state-set; re-verificar fidelidad fuente y gates afectados. Hasta la propagación, los artefactos vigentes quedan desactualizados. Requiere aprobación humana (HITL) antes de propagar.
